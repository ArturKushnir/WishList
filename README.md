# Мій вішліст 💝

Статичний сайт-вішліст для GitHub Pages.

- навігаційна панель по розділах (липка, підсвічує поточний розділ);
- гості можуть **бронювати** подарунки (і скасовувати свою бронь);
- адміністратор (кнопка 🔑 праворуч у меню) може **додавати, редагувати й видаляти** товари та знімати бронь.

## Файли

| Файл | Що там |
|---|---|
| `index.html` | розмітка й стилі |
| `app.js` | логіка: рендер, навігація, бронювання, адмінка |
| `data.js` | вбудовані товари, розділи, список книжок |
| `img/` | фото вбудованих товарів |
| `firebase-config.js` | підключення до бази Firebase |
| `firestore.rules` | правила доступу до бази |

## База

Спільні дані (бронювання й товари, додані адміном) зберігаються в безкоштовній базі **Firebase Firestore**, проєкт `sasha-wishlist-44ii` (<https://console.firebase.google.com/project/sasha-wishlist-44ii/firestore>). Налаштування підключення лежать у `firebase-config.js`.

- колекція `items`: товари, додані або змінені адміном (вбудовані товари лежать у `data.js`);
- колекція `reservations`: бронювання.

Оновити правила доступу: `firebase deploy --only firestore`.

Фото, які адмін завантажує з телефона чи комп’ютера, стискаються в браузері (~50–150 КБ) і зберігаються прямо в базі, тож платний Firebase Storage не потрібен.

## Безпека

Свідомо мінімальна: логін адміна перевіряється в браузері (у коді лежить лише SHA-256 хеш, не сам пароль), а база відкрита на запис. Для особистого вішліста цього достатньо, але технічно обізнана людина могла б змінити дані напряму.

## Локальний запуск

```bash
python3 -m http.server 8000
```

і відкрити <http://localhost:8000>.
